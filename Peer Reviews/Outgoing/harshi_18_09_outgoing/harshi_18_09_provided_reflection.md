# The Reflection: Machine Learning on Databricks Workshop

In March, I attended a “Machine Learning on Databricks” workshop hosted by the UWA Data Science Club. I attended because I wanted to learn about tools currently being used in data science and use this as a way of keeping up with how the field is continuing to develop. The session included an introduction to the Databricks platform and then a hands-on component where we worked through an end-to-end machine learning workflow.

One of the main things I took away from the workshop was that machine learning involves much more than just choosing a model and training it. Before the workshop, I thought about an ML project as preparing the data and extracting its features before training a model and then evaluating its performance. Seeing the Databricks workflow showed me that there are many other stages that could be involved such as data verification, versioning, experiment tracking, managing environments, deployment and monitoring. This changed how I think about what an end-to-end machine learning project actually means.

This was particularly relevant to my own neuroscience project. In my NPSC project, I have focused heavily on preparing the functional connectivity data and building models to later compare their performance. The workshop made me realise that even though these are important parts of the project, they're only one specific part of the full "machine learning lifecycle".  

We also spent time working through GitHub and how it can be used within a collaborative machine learning workflow. Even though I already used GitHub in my university projects, I mainly used it to store code. After this workshop, I saw how it could be used for version control and collaboration, particularly when there are multiple people working on the same project.

This connected me to my initial self-assessment, where I stated that "Understanding current trends and developments" was an area in which I was still developing. I had a technical foundation in Python and machine learning, but I realised that I didn't always actively keep up with the tools and practices being used outside of my coursework. Attending this workshop was one way I could take more initiative in developing that knowledge.

Overall, the workshop changed my understanding of what technical development in data science involves. Previously, I mainly focused on learning Python and R and machine learning techniques, but I have come to realise that understanding the surrounding tools and workflows is also an important part of becoming a data scientist.
