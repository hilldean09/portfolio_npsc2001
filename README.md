# Stylistic Features to Note

## Independent Study Contract (ISC) Achievement Outcome Referencing

When referencing my ISC achievement outcomes I do so in the form of *<OUTCOME CATEGORY> <OUTCOME INDEX WITHIN CATEGORY>*. For example, if I wished to reference the outcome "\[r\]esponding constructively to the opinion of others", I would write *Teamwork 3*. When referencing multiple outcomes within the same category the indexes are delimited by ampersands (&), for example if I wished to reference "\[e\]asily adjusting to a new situation" and "\[m\]apping out ideas to an action plan" I would do so via *Initiative and Enterprise 1 & 2*.

These references can either be parenthesised or not and are used to indicate that the current sentence or paragraph relates to the specific ISC achievement outcomes.

## Artefact Referencing

Throughout my reflections I reference artefacts in the form *Artefact: ```<ARTEFACT FILE NAME>```*. For example: the magnum opus of my project to date is an image of a blue square showing that the method of manufactured solutions run over my conformed mesh has achieved near machine precision as can be seen in *Artefact: ```mms_error_paraview.png```*. The file name seen in my artefact referencing does not contain the full relative path, instead all files referenced in this manner can be found in the *```Artifacts```* subdirectory found at the root of this repository (please excuse the difference in spelling).

## Referencing My Peers' Names

You may notice that I have avoided using the full name of my peers during peer reviews. As my assessment is being submitted as a public GitHub repository, I have avoided including their full names to respect their digital privacy. As it stands I have not come across two of my NPSC2001 peers who share the same first name, so this convention should be unambiguous.
